# 画像成稿

报告头必须有：区间、数据源、支路、岗位切片、样本上限，并写 **「基于现网过程数据的画像框架，不是绩效考核」**。中文。数字用表。主题用标签，不贴 prompt。

五维与计分见 [rubric.md](rubric.md)。缺维写不足，不凑总分。

## 单人

```markdown
# 工作画像 · {email 或 userId}

- 区间：{from} ~ {to}
- Report User：`{userId}` / {email}
- 岗位切片：全栈/骨干 | 需求 | 开发 | 架构 | QA
- 数据源：…
- 样本：aggregate 全量；明细 {n} 条
- 框架：Atlas 人员技能评定（过程证据）

## 一句话人设
{工作方式，不是人格审判。}

## 建议等级
{L1–L4 或「不够定级」} — 依据：{哪些评分卡格子}。缺格则「至多 Lx」。

## 五维
| 维 | 档 | 证据 |
|---|---|---|
| A 流程纪律 | 高/中/低/不足 | 角色覆盖、漏斗 |
| B 并行效率 | | 峰值并行度、并行占比、平均并行度 |
| C 领域深度 | | Role 1/3、doc |
| D 工程效率 | | 耗时、空转 vs 中位 |
| E 工具熟练 | | 版本、explore、Catalog |

## 评分卡
| 指标 | 值 | 对照示例阈值 |
|---|---|---|
| 企业链完成率或角色覆盖 | | ≥80% / 出现 1·3·4 |
| 任务成功率 | | ≥70% |
| 文档产物比 | | 1/3 任务才适用 |
| 代码产物比 | | 实现类才适用 |
| 峰值并行度 | | ≥2 为会并行 |
| 空转指数 | | ≤1.5× 团队中位 |
| 评审债 | 未抽检 / … | |
| 模型合规 | 无分配表则删除本行 | |

## 活跃与成效
| 任务 | 成功 | 失败 | 取消 | 成功率 | Tokens | 产物 |
|---|---|---|---|---|---|---|

时段、失败成簇（status + 主题，不贴 error）。

## 工作方式
Agent 表（任务 / 产物 / tokens）。解读：企业链 vs 小改动路径 vs 纯 explore。

## 模型
Catalog ID 排行；Routing 作注解。

## 产出与项目
kind 比例、cwd 簇。

## 任务主题
description 聚类。全是 `<user_query>` 则写数据不足。

## 建议
最多三条，对应该维的短板（流程 / 模型 / 工作目录 / 上报口径）。无证据的删掉。
```

成功率分母 = 该用户区间任务数。明细被 limit 砍过时，主题节注明样本。

## 多人

```markdown
# 工作画像 · 多人对照

- 区间 / 范围 / 数据源 / 岗位切片（团队默认全栈）
- 框架：Atlas 人员技能评定（过程证据）
- anonymous 已排除排名（单独写占比）

## 格局
人数、任务、成功率、Catalog 数。漏斗：窗口内出现 Role 1 / 3 / 4 / 6 / 评审痕迹的人数。

## 对照
| Report User | 任务 | 成功率 | 峰值并行 | 空转指数 | 主 Agent | 角色覆盖 | 建议等级 |
|---|---|---|---|---|---|---|

角色覆盖写成 `1·3·4` 或 `plan` / `explore`。峰值并行 = 同时在跑的最大任务数。空转 = 相对中位倍数。

## 分化
- 产量 vs 成功率 vs 空转 vs 峰值并行（高产全串行、高峰并行要点名）。
- 热力：谁在跑企业链，谁全是 plan/explore（后者在 standard 小改动上可能合理）。
- 模型气泡：Catalog × Token × 成功率。某模型 Token 高成功率低 → 先调分配，不先怪个人。
- 项目重叠：cwd 末段。

## 异常
全失败、只有取消、只有 anonymous、单日占满、超长 duration、空转 ≫ 1.5×。没有则省略。

## 建议
面向团队模型、插件是否启用、门闩是否打开，最多三条。
```

超过约 12 人时正文只留 Top 与两端异常。不要输出 N 份互不引用的单人模板。

## HTML 与 Canvas

Markdown 是底稿。再写同名自包含 HTML（可离线打开）。Cursor 另写 Canvas：数字内联；图有标题、轴单位、图例、区间与数据源；没数据的块不画。五维用表或条，不要空雷达框。
