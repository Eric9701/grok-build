# Atlas Relay 协议

浏览器聊天页（Relay Client）与本机 `atlas agent headless`（Relay Agent）之间的约定。中继进程只做分槽和透传，不改 ACP 正文，也不校验 JWT。

术语见 [CONTEXT.md](../CONTEXT.md)。启动步骤见 [README.md](../README.md)。

## 角色

| 角色 | 谁 | 连接 |
|---|---|---|
| Relay Agent | `atlas agent headless` | 出站连 `/ws` 或 `/ws/agent` |
| Relay Client | 浏览器聊天页 | 连 `/ws/client` |
| 中继 | `atlas-relay-demo` | 按 Agent Identity 把两边配成一对 |

一个 Relay Client 同时只绑一个 Agent。一个 Agent 同时只留一个 Client，后来者抢走绑定。

## 连接

默认监听本机局域网 IPv4 的 `2420`。可用 `-addr host:port` 改。

### Agent

```text
ws://<中继IP>:2420/ws?agent_id=<身份>
```

`/ws/agent` 与 `/ws` 相同。身份按下面顺序取，去掉首尾空白和换行，最长 128 字符：

1. 查询参数 `agent_id`
2. 请求头 `x-userid`
3. `anonymous-<递增序号>`

同一身份再次连上时，新连接顶掉旧连接。掉线后登记还在，`online` 变为 false；同身份重连后，已绑定的页面可以继续发 ACP。

CLI 还必须带 `--grok-ws-origin http://<中继IP>:2420`，与浏览器打开的页面同源。模型用 `atlas agent` 上的 `-m` / `--model`，写在 `headless` 前面，值是 Catalog ID：

```bash
atlas agent --always-approve -m <Catalog ID> headless \
  --grok-ws-url "ws://<中继IP>:2420/ws?agent_id=laptop-a" \
  --grok-ws-origin http://<中继IP>:2420
```

查询串里的 `token` 和请求头 `X-XAI-Token-Auth` 只打日志，不参与鉴权。

### Client

```text
ws://<中继IP>:2420/ws/client
```

页面地址是 `http://<中继IP>:2420/build`。手机用 `http://<中继IP>:2420/m`（`/h5` 相同）。两页都连 `/ws/client`，ACP 相同。`?agent=<身份>` 只作为页面初次选中的身份，不是 WebSocket 查询参数。

只有一个 Agent 在线且还没被占用时，新页面会自动绑上。多个在线时要发 `atlas.relay/bind`。

### 帧

- WebSocket 文本帧或二进制帧，正文是一条 JSON。
- 单帧上限 8 MiB。发送队列 64 条，满了丢帧。
- 中继每 15 秒发 WebSocket Ping；60 秒没有 Pong 则断开。
- 正文是 `ping`（可带首尾空白）的帧丢弃，不转发。
- 方法名以 `atlas.relay/` 开头的帧由中继消费，不转给对端。其余帧原样转给当前绑定的另一端。对端不在线时丢弃。

## 中继方法

这些方法不进入 ACP。

### `atlas.relay/bind`

Client → 中继。无 `id` 时当作通知，中继不回 result。

```json
{
  "jsonrpc": "2.0",
  "method": "atlas.relay/bind",
  "params": { "agentId": "laptop-a" }
}
```

`agentId` 与 `agent_id` 都认。空身份忽略。换绑会解开旧身份；若目标身份已有别的页面，那个页面的绑定被清空，它要重新选择。

### `atlas.relay/status`

中继 → 每个已连接的 Client。Agent 上下线或绑定变化时推送。没有 `id`。

```json
{
  "jsonrpc": "2.0",
  "method": "atlas.relay/status",
  "params": {
    "agents": [
      { "id": "laptop-a", "userId": "zhang", "version": "0.2.143", "online": true }
    ],
    "boundAgentId": "laptop-a"
  }
}
```

`userId`、`version`、`boundAgentId` 可省略。当前绑定的 Agent 掉线时仍出现在 `agents` 里，`online` 为 false。

## ACP 调用

Client 与 Agent 之间是 JSON-RPC 2.0。带 `id` 的请求，Agent 回 `result` 或 `error`。中继不改这些字段。

聊天页在发业务方法前先 `initialize` 一次。cwd 取页面输入；空则传 `"."`（Agent 进程的工作目录）。指定模型时 `_meta.modelId` 和 `session/set_model` 的 `modelId` 都是 Catalog ID。

### `initialize`

```json
{
  "jsonrpc": "2.0",
  "id": 1,
  "method": "initialize",
  "params": {
    "protocolVersion": 1,
    "clientCapabilities": {
      "fs": { "readTextFile": false, "writeTextFile": false },
      "terminal": false
    },
    "_meta": {
      "clientIdentifier": "atlas-relay-demo",
      "clientType": "atlas-relay-demo",
      "startupHints": { "nonInteractive": true }
    }
  }
}
```

结果 `_meta.modelState` 是模型目录（与 CLI `/model` 同一份）。`_meta.availableCommands` 是内置斜杠的初值。

### `session/new`

新建会话。`_meta.sessionId` 必须是 UUID；省略则由 Agent 生成。`_meta.yoloMode` 固定为 true。选了模型才带 `modelId`。

```json
{
  "jsonrpc": "2.0",
  "id": 2,
  "method": "session/new",
  "params": {
    "cwd": "/opt/kb/kb server",
    "mcpServers": [],
    "_meta": {
      "yoloMode": true,
      "sessionId": "018f2c3a-7b1e-7c2a-8d4e-6b5a4c3d2e1f",
      "modelId": "arch-kimi-code-eric"
    }
  }
}
```

成功时 `result.sessionId` 为会话 id。

### `session/load`

载入已有会话。不用 `session/resume`。载入成功后，若页面选了模型，再发一次 `session/set_model`。

```json
{
  "jsonrpc": "2.0",
  "id": 3,
  "method": "session/load",
  "params": {
    "sessionId": "018f2c3a-7b1e-7c2a-8d4e-6b5a4c3d2e1f",
    "cwd": "/opt/kb/kb server",
    "mcpServers": []
  }
}
```

### `session/set_model`

会话已就绪时切换模型。

```json
{
  "jsonrpc": "2.0",
  "id": 4,
  "method": "session/set_model",
  "params": {
    "sessionId": "018f2c3a-7b1e-7c2a-8d4e-6b5a4c3d2e1f",
    "modelId": "arch-kimi-code-eric"
  }
}
```

### `session/prompt`

用户消息和斜杠命令都走这里。斜杠是提示词正文，不是单独的 RPC。

```json
{
  "jsonrpc": "2.0",
  "id": 5,
  "method": "session/prompt",
  "params": {
    "sessionId": "018f2c3a-7b1e-7c2a-8d4e-6b5a4c3d2e1f",
    "prompt": [{ "type": "text", "text": "看一下进度" }]
  }
}
```

### `session/cancel`

通知，无 `id`。停止当前轮。

```json
{
  "jsonrpc": "2.0",
  "method": "session/cancel",
  "params": { "sessionId": "018f2c3a-7b1e-7c2a-8d4e-6b5a4c3d2e1f" }
}
```

### Agent 推给 Client 的通知

| 方法 | 页面做什么 |
|---|---|
| `session/update` | 看 `params.update.sessionUpdate` |
| `x.ai/session_notification` | 同上，更新在 `params` 或 `params.update` |
| `session/request_permission` | 自动选 `allow_once`，没有则选第一项；没有选项则取消 |
| `x.ai/models/update` | 用 `params.availableModels` 刷新模型下拉 |

`session/update` 里页面识别的 `sessionUpdate`：

| 值 | 含义 |
|---|---|
| `agent_message_chunk` | 助手正文，`content.text` |
| `agent_thought_chunk` | 思考，纯文本 |
| `tool_call` / `tool_call_update` | 工具行 |
| `available_commands_update` | 斜杠目录，`availableCommands` |

权限应答（带上原请求的 `id`）：

```json
{
  "jsonrpc": "2.0",
  "id": 9,
  "result": {
    "outcome": { "outcome": "selected", "optionId": "allow-once" }
  }
}
```

仍建议 CLI 加 `--always-approve`，少走这轮往返。

## 扩展方法

扩展方法的 JSON-RPC `result` 外包一层 `{ "result": <正文> }`。页面先读内层 `result`。

### `x.ai/models/list`

模型下拉，与 CLI `/model` 同一目录。可在没有会话时调用（`initialize` 之后）。

```json
{ "jsonrpc": "2.0", "id": 6, "method": "x.ai/models/list", "params": {} }
```

正文：

```json
{
  "currentModelId": "arch-kimi-code-eric",
  "availableModels": [
    { "modelId": "arch-kimi-code-eric", "name": "Kimi", "description": "" }
  ]
}
```

下拉显示 `name`，提交 `modelId`。

### `x.ai/session/list`

历史会话。用这个方法，不用 `x.ai/sessions/list`（那份名单会丢掉 headless）。

```json
{
  "jsonrpc": "2.0",
  "id": 7,
  "method": "x.ai/session/list",
  "params": {
    "cwd": "/opt/kb/kb server",
    "headless": "include",
    "limit": 40,
    "allowRelax": true
  }
}
```

`headless` 为 `include` 时 TUI 与 headless 都列出。`allowRelax: true` 时，当前目录没有会话会放到仓库或全部目录再找。

正文里每条会话是扁平对象，常用字段：`sessionId`、`title`、`summary`、`cwd`、`updatedAt`、`modelId`。点一条会把 `sessionId` 和 `cwd` 填进页面，再走 `session/load`。

### `x.ai/commands/list`

会话建立后拉斜杠目录。`initialize` 的 `availableCommands` 和 `available_commands_update` 是另外两条来源，页面取较新的一份。

```json
{
  "jsonrpc": "2.0",
  "id": 8,
  "method": "x.ai/commands/list",
  "params": {
    "sessionId": "018f2c3a-7b1e-7c2a-8d4e-6b5a4c3d2e1f",
    "cwd": "/opt/kb/kb server"
  }
}
```

正文的 `commands` 是斜杠数组。中继不扫描 `~/.atlas/skills`。

## 命令

聊天页没有自己的斜杠执行器。`/model`、`/theme` 这类只在 TUI 里生效的命令，在这里不会当本地命令跑。

| 用户操作 | 线上行为 |
|---|---|
| 输入 `/` | 用已收到的目录做补全，不发 RPC |
| 点「命令」 | 打开本页面板 |
| 输入 `/skills` 或 `/skill` | 只打开本页面板，不发给 Agent |
| 选中一项再 Enter，或直接发送 `/name …` | `session/prompt`，正文就是这行字。主指针是触控时，菜单没打开则回车只换行 |
| 模型下拉 +「应用」 | `session/set_model`，不是 `/model` |
| 「历史」 | `x.ai/session/list`，再 `session/load` |

真正执行技能，是把目录里已广告的名字发给 Agent，例如 `/commit` 或 `/atlas-sdd:4-software-engineer-agent`。

## HTTP（不走 WebSocket）

| 路径 | 作用 |
|---|---|
| `GET /healthz` | 正文 `ok` |
| `GET /status` | `{ "agents": [ { "id", "userId", "version", "online" } ] }`，只含在线 Agent |
| `GET /`、`GET /build` | 桌面聊天页 |
| `GET /m`、`GET /h5` | 手机 H5 聊天页 |
| `GET /slash.js`、`GET /md.js`、`GET /chat.js` | 补全、Markdown、共用会话逻辑 |
| `GET /sample-docs/…` | 示例需求、设计、验收 |
| `POST /dispatch/prompts` | 只生成三轮派工文案，不替 Agent 拉网 |

`POST /dispatch/prompts` 请求：

```json
{
  "jobId": "pay-20260901",
  "requirementsUrl": "https://example/requirements.md",
  "designUrl": "https://example/design.md",
  "acceptanceUrl": "https://example/acceptance.md"
}
```

三个 URL 必须是 http 或 https。响应里的 `drop`、`execute`、`report` 由页面依次用 `session/prompt` 发出：落盘、只跑 `atlas-sdd:4-software-engineer-agent`、写出 `documents/execution-report-<jobId>.json`。cwd 必须是业务仓根。
