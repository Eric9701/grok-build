Tier1 必备

快速入门

安装

Atlas 是终端 AI 编程助手，以全屏 TUI 运行，可理解代码库、执行命令、编辑文件、搜索网络并管理任务。支持交互式 TUI、无头脚本模式，以及通过 ACP 集成到编辑器。

企业/内网（本仓库示例）：

# Windows PowerShell
irm http://10.218.220.237:22255/atlas/cli/install.ps1 | iex

# macOS / Linux / Git Bash
curl -fsSL http://10.218.220.237:22255/atlas/cli/install.sh | bash

PowerShell 安装器会自动将 %USERPROFILE%\.atlas\bin 加入用户 PATH。验证与更新：

atlas --version
atlas update

首次启动

运行 atlas。凭据保存在 ~/.atlas/auth.json 并自动刷新。

  • 企业部署：推荐 atlas login --device-auth（设备码，先在浏览器登录 atlas-server）
atlas login --device-auth
export XAI_API_KEY="xai-..."
atlas

基本交互

TUI 两大区域：

  • Scrollback（回滚区） — 对话历史、工具调用、文件编辑等
  • Prompt（输入区） — 底部输入，Enter 发送

Tab 在 prompt 与 scrollback 间切换。运行中 Esc 可取消回合（fullscreen vim 模式例外）；空闲时连按两次 Esc（800ms 内）可清空输入或打开 rewind。

@ 文件引用

@src/main.rs              # 附加文件
@src/main.rs:10-50        # 附加行范围
@src/                     # 浏览目录
@!.github                 # 搜索隐藏文件（前缀 !）

权限

默认执行命令或编辑文件前会询问。可 Ctrl+O 切换 always-approve、启动时 --yolo，或输入 /always-approve。

核心概念

会话（Session）

每次对话即一个会话，自动保存到 ~/.atlas/sessions/。

  • 新会话：Ctrl+N 或 /new
  • 恢复：/resume 或 atlas --resume <ID>
  • 继续最近：atlas -c

工具说明

常用启动选项

atlas "fix the failing auth test"          # 带初始 prompt
atlas --worktree=feat "refactor module X"  # 新 git worktree
atlas -w --ref main "implement feature"     # 基于指定分支
atlas --cwd ~/projects/my-app
atlas --rules "Always use TypeScript."
atlas --yolo
atlas -m atlas-build
atlas --resume <session-id>
atlas -c
atlas --minimal    # 实验性 scrollback-native 模式
atlas --fullscreen # 标准全屏 TUI
atlas -p "Explain this codebase"  # 无头模式

无头输出格式

格式标志说明
plain默认人类可读文本
json--output-format json含 text、stopReason、sessionId
streaming-json--output-format streaming-jsonNDJSON 事件流
atlas -p "Review changes" --output-format json --yolo | jq -r '.text'

Tier1 必备

身份验证

浏览器登录（默认）

重新登录：atlas login；登出：atlas logout。

标志说明
--device-auth（别名 --device-code）设备码流程（无头/远程/企业推荐）

企业设备码登录

atlas login --device-auth
  1. 终端打印 URL 与 user_code
  2. 浏览器先登录企业 atlas-server，再填入设备码与账号机器码
  3. CLI 轮询至批准；refresh 落服务端 MySQL，重启 atlas-server 一般不丢会话
  • VS Code / Cursor 未登录引导也走 atlas login --device-auth，不要用裸 atlas login。

Simple（默认）：方向键导航，任意字母键聚焦 prompt。

Vim：在 [ui] vim_mode = true 或 /vim-mode 启用；j/k 导航，h/l 折叠。

⇧HShift+Left上一 turn

视图

键替代动作

lRight展开
e切换折叠
⇧E全部展开/折叠
y / ⇧Y复制内容/元数据

Esc 行为

状态效果
运行中（默认模式）Esc 立即取消（保留草稿）
运行中（fullscreen vim）Esc 无操作；用 Ctrl+C
空闲 + 非空 prompt800ms 内双 Esc 清空并暂存草稿（Ctrl+S 可恢复，含图片）
空闲 + 空 prompt + 有消息双 Esc 打开 rewind

代理级

键动作
Ctrl+P / ?命令面板
Ctrl+M模型选择（prompt 聚焦时切换多行）
Ctrl+O切换 always-approve
Ctrl+S / Alt+S暂存 / 弹出输入草稿（空 composer 恢复最近一次；发送后自动还原）
F3会话选择器（欢迎页与会话内均可；等同 /resume）
Ctrl+Gminimal 下用外部编辑器改现有草稿（全屏用命令面板或 /edit-prompt）
Ctrl+B前台命令转后台
Shift+Tab循环模式 Normal→Plan→Auto（功能开启时）→Always-approve
↑（空 prompt）有排队则聚焦队列末行；否则浏览本会话 prompt 历史
!Shell 模式

运行中发送：Ctrl+Enter（VS Code 族用 Ctrl+L）立即发送并取消当前 turn。

全局

键动作确认
Ctrl+N新会话是（1s 内连按）
Ctrl+\Agent Dashboard否
Ctrl+Q / Ctrl+D退出是

VS Code 族终端：Ctrl+Q 被宿主捕获，退出仅用 Ctrl+D；半页下滚为 Shift+D；插话用 Ctrl+L。

阻塞卡片（问题/权限/取消）

三种阻塞界面共享键盘契约：Tab/Shift+Tab 在卡片内循环，不跳出；Esc 逐级退出。

Tier1 必备

配置

优先级

（高→低）CLI 标志 → 环境变量 → requirements.toml/MDM → GROK_CONFIG 覆盖层 → config.toml → managed_config.toml → 内置默认。

GROK_CONFIG 为 JSON 深度合并覆盖层，受 allowlist 限制，不能提权。

GROK_CONFIG='{"models": {"default_reasoning_effort": "high"}}' atlas agent stdio

Tier2 核心

MCP 服务器

配置

[mcp_servers.my-server]
command = "/path/to/server"
args = ["--flag"]
env = { API_KEY = "sk-..." }
enabled = true
startup_timeout_sec = 30
tool_timeout_sec = 6000

[mcp_servers.remote]
url = "https://mcp.example.com/api"
headers = { Authorization = "Bearer ${TOKEN}" }

工具命名：server__tool。大结果默认截断 20000 字节，可用 [mcp] max_output_bytes 或 GROK_MAX_MCP_OUTPUT_BYTES 调整。

Hooks

事件

事件时机可阻塞
SessionStart/End会话起止否
UserPromptSubmit提交 prompt否

PostToolUse工具成功后否

}

Agent 模式与 ACP

什么是 ACP

Agent Client Protocol 用 JSON-RPC 让 IDE / SDK / 自定义客户端与编码 Agent 通信。一次性提问并退出请用 atlas -p（见 无头模式）。

覆盖能力：会话创建/加载/恢复、prompt 与流式回复、工具调用更新、推理流、非 always-approve 时的权限提示。

传输方式

# stdio（本地 / 多数 SDK / VS Code 扩展）
atlas agent --always-approve stdio

# WebSocket 服务（跨客户端保活）
atlas agent --always-approve serve --bind 127.0.0.1:2419 --secret <token>

# 通用选项在 mode 名之前
atlas agent --always-approve --model atlas-build stdio
标志说明
-m / --model模型 ID
--always-approve / --yolo跳过交互权限提示（deny 规则与 hooks 仍生效）
--reauth启动前重新认证
--agent-profile从文件加载 agent profile
--leader / --no-leader共享 leader 或强制本地；沙箱非 off 时拒绝 leader

亦可在 session/new 的 _meta.yoloMode 按会话开启 always-approve。省略 --secret 时启动打印生成令牌，或设 GROK_AGENT_SECRET。

GROK_CONFIG 可用于 harness 注入软设置。VS Code / Cursor 的 Atlas 扩展通过 ACP 拉起同一套 CLI。

内置 Profile

默认关闭。启用后由 OS 内核原语限制进程生命周期内的文件系统与网络（Linux Landlock、macOS Seatbelt）。

Profile读写子进程网络场景
off（默认）无限制无限制允许无沙箱

权限模式

模式说明场景
default (ask)危险操作需确认日常交互

规则

在 ~/.atlas/config.toml 或 .atlas/config.toml：

[[permission]]
tool = "Bash"
action = "deny"
pattern = "rm -rf *"

[[permission]]
tool = "Edit"
action = "allow"
pattern = "src/**"

合并优先级：deny > ask > allow。多文件 permission 规则合并，非覆盖。

规则匹配参考

前缀控制对象
Bash(...)Shell 命令（* 含空格）
Edit(...) / Write(...)文件编辑/写入路径

MCPTool(...)MCP 工具调用

项目 .atlas/config.toml / .claude/settings.json 的权限规则受 folder trust 门控：未信任的仓库会跳过这些规则并弹出信任询问。已记住的交互授权在 Atlas Home sessions/<编码后的项目根>/permission.toml；删文件即重置该项目授权。

  • 跳过安装：环境变量 GROK_SKIP_ATLAS_SDD=1 / GROK_SKIP_ATLAS_SKILLS=1。

/ask-atlas（Main Flow）

在项目根目录启动 atlas（或 VS Code / Cursor 侧边栏），输入 /ask-atlas 并描述意图。它会按情况选技能或企业阶段，而不是立刻写代码。

主流程：想法 → 交付

  1. /grill-with-docs — 在工作目录里拷问，沉淀 CONTEXT.md / ADR（无工作目录时用 /grill-me）。
  2. 能否在对话里说清？ 需要可运行答案时，经 /handoff 进 /prototype，再 handoff 回来。
  3. 是否跨多会话？
    • 是 → /to-spec → /to-tickets → 每个票据单独 /implement（票据间 /clear）
    • 否 → 同会话直接 /implement

/implement 内部按 /tdd 红绿切片，收尾跑 /code-review（Standards + Spec 双轴）。单独用 /tdd / /code-review 也可。

拷问 → 出票尽量保持同一上下文窗口，不要过早 /compact；每个 /implement 再开干净上下文。

汇入主流程的入口

场景技能
堆积的缺陷 / 外来需求/triage（不要 triage /to-tickets 已产出的票）
难复现 / 间歇 / 回归/diagnosing-bugs（先有变红的复现命令再改）
超大、方向不清的工程/wayfinder（出决策图，再并入 /to-spec，不要直接 implement）
空闲时改善可维护性/improve-codebase-architecture

常用斜杠一览

命令用途
/ask-atlas路由器：按意图选技能或企业阶段
/grill-with-docs拷问并留下 CONTEXT / ADR
/tdd先红后绿实现一个行为
/implement按说明/票据实现（内走 tdd，收尾 code-review）
/diagnosing-bugs硬缺陷诊断
/code-review相对基点做 Standards + Spec 评审
/to-spec / /to-tickets多会话大功能：规格 → 票据

atlas-sdd（Role Executor）

按企业 SDD 阶段执行，遵循插件内 spec/（Enterprise Spec Baseline）；项目可用 .atlas/ / documents/ 做 Project Override。

角色斜杠（阶段）产物目录默认链？
Role 1 需求分析/1-requirement-analystdocuments/requirements-analyst/是
Role 2 架构设计/2-architect-designdocuments/architecture-design/否（Side Ramp）

亦可用 /atlas-sdd（别名 /sdd）选择角色。阶段命令只映射阶段；未拷问时不要用它们跳过 /grill-with-docs。

默认门禁顺序

Grill（父会话 /grill-with-docs）
  → Role 1 需求
  →（可选）Role 2 架构 —— 仅当你明确说「架构 / 架构设计」
  → Role 3 详细设计
  → Role 4 实现（内部 /tdd，不要整包 /implement）
  → Close：父会话 /code-review
       + enterprise-strict 时 Role 6 写测试用例

合规模式（业务仓配置）：

  • standard（默认）— 已有等价详细设计时可不必强制整条角色链
  • enterprise-strict — 拷问后强制 1→3→4→6；Role 2 仍可选

用户话术怎么映射阶段

/ask-atlas 里的名词表示当前阶段，不是「直接召唤会写那种文件的单个角色」：

你说打开的阶段
需求文档Role 1
设计文档 / 详细设计Role 3（不是 Role 2）
架构 / 架构设计可选 Role 2
实现代码Role 4（须已有详细设计）

Role 1 不再做第二轮拷问；缺口回到父会话继续 grill。Role 3 前若无架构文档，会问你指定路径或确认跳过，不会因此自动拉起 Role 2。

三种典型用法

1. 修 bug

/ask-atlas 登录后偶发 401
→ /diagnosing-bugs（或直接 /tdd）
→ /code-review

不跑需求分析 / 架构角色。

2. 小功能（一个会话能说清）

必要时 /grill-with-docs
→ /implement 或 /tdd
→ /code-review

3. 要企业需求/设计文档再实现

/ask-atlas …出需求文档
→ 按提示先 /grill-with-docs（父会话多轮）
→ Role 1 → documents/requirements-analyst/
→ 「设计文档」→ Role 3（可引用已有架构；无则跳过 Role 2）
→ 「实现代码」→ Role 4（红绿）
→ 父会话 /code-review
→（strict）Role 6 → documents/test-cases/

Atlas Home

用户态根目录由 GROK_HOME 解析，默认 ~/.atlas（Windows：%USERPROFILE%\.atlas）。配置、会话、安装登记都落在这里——不要再把 ~/.grok 当当前家目录。

路径用途
config.toml主配置；/settings 写入此处
auth.json登录凭据
sessions/会话持久化
installed-plugins/用户级插件快照 + registry.json
skills/Native Skill（插件技能不在这里）
bin/安装器放入的 atlas / atlas.exe

VS Code / Cursor 扩展

扩展是 CLI 的图形前端，必须先装好 atlas 并能登录。企业 VSIX 示例：

Invoke-WebRequest -Uri http://10.218.220.237:8888/atlas/atlas-vscode-3.1.0.vsix -OutFile atlas-vscode-3.1.0.vsix
code --install-extension .\atlas-vscode-3.1.0.vsix --force
cursor --install-extension .\atlas-vscode-3.1.0.vsix --force
  • 扩展通过 ACP spawn atlas agent stdio，自己不扫 plugins/skills。
  • 侧边栏 UI：+ 新会话、底部 Agent / Plan / Auto accept（不是斜杠）。
  • 起不来或一直要登录：终端先跑通 atlas login --device-auth；检查设置里的 atlas.cliPath。
  • Desktop 更新与 CLI 同一企业通道（如 22255/atlas），不是独立 8888。

遥测与 Task Report

开关作用
telemetry_enabled / GROK_TELEMETRY_ENABLEDsignals / events 等产品遥测
trace_upload_enabled / GROK_TELEMETRY_TRACE_UPLOAD只关会话 trace 产物上传（GCS/S3/proxy），不是总开关
GROK_DISABLE_TASK_REPORT=1关闭 Task Report（默认开；主会话 / plan / 子 agent 都会报）
GROK_EXTERNAL_OTEL客户侧 OTEL 导出（见 第 24 章）

尽量全停：telemetry_enabled=false + trace_upload_enabled=false + GROK_DISABLE_TASK_REPORT=1。

Admin 页：/atlas/admin/task-reports。排行按 Catalog ID；明细含 Model / Routing。

连不上 atlas-server 时启动

代理不可达时，设备码登录、托管模型、远程 settings、自动更新都会失败。本地对话须同时关掉两道门，并配置本地/BYOK 模型。权威步骤见 docs/atlas-runtime-安装手册.md §9。

# ~/.atlas/config.toml
[auth]
require_session_at_startup = false   # 也可 GROK_REQUIRE_SESSION_AT_STARTUP=0

[features]
remote_fetch = false                 # 无环境变量；跳过 /settings 与远程 /models
# 否则 bootstrap 卡 ~40s：Couldn't start … loading your account settings
[model.local]
model = "qwen2.5-coder"
base_url = "http://127.0.0.1:11434/v1"
api_key = "ollama"
api_backend = "chat_completions"

# atlas -m local

恢复内网后：改回 remote_fetch（默认 true）→ atlas login --device-auth → /refresh-model。

配置参考摘要

对应上游 26-config-reference.md（CLI 启动也会解压到 Atlas Home 文档树）。概念说明仍见 第 5 章；完整字段表以英文源或本机解压副本为准。下文路径统一写 Atlas Home（默认 ~/.atlas）。

配置分层（后者覆盖前者，pin 除外）

  1. 编译默认值
  2. /etc/atlas/managed_config.toml 或 $GROK_HOME/managed_config.toml（舰队默认；用户文件可覆盖标为 user 的项）
  3. $GROK_HOME/config.toml（个人；/settings 写这里）
  4. 项目 .atlas/config.toml：通常只贡献 [mcp_servers]、[plugins]、[permission]、[mcp] max_output_bytes
  5. GROK_CONFIG（内联 JSON）或 GROK_CONFIG_PATH（白名单键）
  6. requirements.toml（管理员层；标 pin 的键不可被用户/环境/CLI 覆盖）
  7. GROK_* 环境变量
  8. CLI 标志（如 --model、--sandbox、--yolo）

排查生效值：atlas inspect 或 atlas inspect --json。

三类文件谁写

文件谁写用途
config.toml开发者个人默认，可随时改
managed_config.toml部署/控制台舰队起点，用户可覆盖
requirements.toml管理员（可签名）强制策略；pin 键锁死

常用键速查

键 / 段说明
[ui] vim_mode / screen_mode / permission_modeVim、默认全屏/minimal、权限模式
[model.<id>]自定义或托管落盘模型
[mcp_servers.*]MCP
[plugins] enabled启用的用户级插件名
[memory] enabled跨会话记忆
[features] telemetry / [telemetry] trace_upload遥测门控
[features] remote_fetch是否拉远程 settings /models（断网须 false；无 env）
[cli] channel / auto_update更新通道（企业常配合 atlas-server /cli）
auth.disable_api_key_auth（可 pin）禁止 API Key，只走部署 IdP
[auth] require_session_at_startup启动登录门控（默认开；断网可 false）

外观细节在 pager.toml（见 主题）。完整字段列表见源文档 crates/.../user-guide/26-config-reference.md。
